# Canvas Task Tracker

A personal assignment tracker for students using the Canvas LMS API. Built as a single-page web app hosted on Netlify, designed to solve a common pain point: Canvas requires you to dig into each course individually to find assignments. This app pulls everything together into a single chronological list sorted by due date, so you can see what needs to be done and in what order — across all your courses at once.

Built specifically for use with Montgomery County Public Schools Canvas (`mcpsmd.instructure.com`).

---

## How It Works

The app uses a personal Canvas API token generated by the student from their Canvas account settings. All Canvas API calls are routed through a Netlify serverless function (`netlify/functions/proxy.js`) to work around CORS restrictions on the school's Canvas instance. The HTML file is hosted as a static site on Netlify and can be used from any browser, including mobile.

A simple passphrase protects the app from casual visitors since the repository is public.

---

## Features

- **Assignments sorted by due date** across all courses — no more digging into each class
- **Due date and deadline** both shown when available, so the difference between when something is due and when Canvas stops accepting submissions is clear
- **Overdue & missing section** split into two subsections:
  - Still accepting submissions (sorted by deadline, soonest first)
  - No longer accepting submissions
- **Course filter** — multi-select checkbox dropdown to filter by one or more courses, with selections saved between sessions
- **Status filter** — Active (actionable items only), Closed (no longer submittable), All, Done
- **Summary strip** showing assignments due in the next 7 days and overdue count, updating with course filter selection
- **Personal tasks** — add your own tasks with a due date and optional course tag, stored alongside Canvas assignments
- **Check off assignments** — mark anything complete; state persists between sessions
- **Dark mode** support via CSS media query
- **Mobile responsive** — designed for use on a phone since school Chromebooks block the app
- **Passphrase login screen** to prevent casual access

## Setup

### 1. Canvas Token

1. Log into Canvas at `mcpsmd.instructure.com`
2. Go to **Account → Settings → Approved Integrations**
3. Click **+ New Access Token**, give it a purpose (e.g. "Task Tracker"), leave expiry blank
4. Copy the token immediately — Canvas only shows it once

### 2. Using the App

1. Open [https://canvas-tracker.netlify.app](https://canvas-tracker.netlify.app)
2. Enter the passphrase
3. Enter the Canvas domain (`mcpsmd.instructure.com`) and paste the token
4. Hit **Connect** — the domain and token are saved to localStorage so you won't need to re-enter them

### 3. Local Development

Since the app makes API calls to Canvas through the Netlify proxy, running it as a local `file://` will hit CORS errors. Options:

- **Python**: `python -m http.server 8000` in the project folder, then open `http://localhost:8000`
- **VS Code**: use the Live Server extension
- **Netlify CLI**: `netlify dev` to run the full stack including functions locally

## Current Limitations

State (personal tasks, completed checkboxes, course filter) is stored in **browser localStorage**, which means:

- Data is tied to the specific browser and device
- Clearing browser data wipes everything
- No sync across devices (phone, tablet, computer)

---

## Planned: Cross-Device State with Supabase

The next phase of development will replace localStorage with a proper backend to make state follow the user across devices. The planned stack:

### Database (Supabase + Postgres)

Two tables:

```sql
personal_tasks (
  id          text primary key,
  user_id     uuid references auth.users,
  title       text,
  due_at      timestamptz,
  course_id   text,
  created_at  timestamptz default now()
)

user_state (
  user_id        uuid primary key references auth.users,
  completed_ids  text[],
  course_filter  text[]
)
```

### Authentication

Supabase built-in Google OAuth — the student signs in with their Google account. No separate user management needed.

### API Layer

Two new Netlify Functions alongside the existing Canvas proxy:

- `netlify/functions/state-read.js` — fetches personal tasks and user state for the authenticated user
- `netlify/functions/state-write.js` — writes personal tasks and user state

The app will never talk to Supabase directly. All database access goes through these functions so Supabase credentials stay server-side. The Supabase URL and service key will be stored as Netlify environment variables.

### What Changes in the App

The `LS.get()` and `LS.set()` calls for personal tasks, completed IDs, and course filter will be replaced with fetch calls to the new Netlify functions. A Google sign-in button will replace the current passphrase screen, providing both authentication and cross-device identity in one step.

localStorage can be kept as a fallback cache for offline use or to reduce API calls on initial load.

---

## Notes

- The Canvas proxy (`proxy.js`) is hardcoded to `mcpsmd.instructure.com`. To use with a different Canvas instance, update `CANVAS_BASE` in that file and redeploy.
- The passphrase is hardcoded in `index.html`. It provides basic protection against casual visitors but is not cryptographically secure — anyone who downloads and reads the HTML can find it. This will be replaced by Supabase auth in the next phase.
